Chapter 01

Install Windbound Bard

You’ll need FFXIV, a compatible Dalamud environment, and the Windbound Bard plugin. The published repository currently offers an install manifest for Dalamud.

  1. Launch FFXIV with Dalamud, then enter /xlsettings in chat.
  2. Open Experimental → Custom Plugin Repositories.
  3. Paste the custom repository URL below, select +, enable the entry and choose Save and Close.
  4. Enter /xlplugins, search for Nunu’s Windbound Bard and install it.
  5. In chat, enter /windbound to open the player.
https://raw.githubusercontent.com/BTYRE1916/NunuWindboundBard-FFXIV/master/Plugin.json
ⓘFor a source/development build, use Dalamud’s Dev Plugin Locations as described in the complete manual. Custom repos are third-party software and are not vetted by Dalamud’s main repository.
Chapter 02

Play your first MIDI

  1. Use /windbound to open the plugin.
  2. In Ensemble, choose Solo.
  3. Open Songs & Playback. Select Load sample for Bard-37-Note-Calibration.mid, or browse for a .mid / .midi file.
  4. Choose a Performance instrument and open the full 37-key Performance interface.
  5. Enable ARM: Direct FFXIV Performance notes. This is the safety switch that allows notes into the game.
  6. Try Direct Output & Test → Test C4, then press Play. Use STOP to finish.

What does ARM mean?

Without ARM, the timeline may progress without sending notes to FFXIV. Windbound does not restore ARM after a plugin restart—you deliberately enable it for every new session.

Chapter 03

37 keys. One full range.

Chapter 05

From duet to octet

Use native FFXIV Ensemble for coordinated starts. Each Bard needs the same plugin version, the identical MIDI available locally, a Performance instrument and the expanded keyboard.

On the conductor

  1. Be the actual in-game party leader; choose Conductor on the Ensemble tab.
  2. Load the MIDI into your Ensemble library.
  3. Assign each track/channel to a Bard; use SET PARTY TRACKS.
  4. Use SET PARTY INSTRUMENTS, or Concert Director’s PREPARE ENTIRE ORCHESTRA.
  5. Press ARM ALL BARDS and wait for readiness acknowledgements.
  6. Press START ENSEMBLE — FFXIV Ready Check.

On each follower

  1. Select Follower and enable the native Ensemble option.
  2. Permit leader MIDI/instrument sync and optional ARM control as desired.
  3. Ensure the same MIDI file exists in that client’s library and Performance is ready.
  4. Allow automatic FFXIV Ensemble Ready Check acceptance if appropriate, or accept manually.

Important: the conductor sends a MIDI fingerprint, not the actual file; matching file names alone may not be enough. The game’s native cue starts the song, not a party-chat countdown.

Chapter 06

Design your stage

Stage Formations supports saving current party positions or designing a top-down layout of numbered performer dots. For automatic walking, each client needs the optional vnavmesh plugin and explicit follower permission.

  1. Get everyone into the same party, stage, ward and instance.
  2. Open Stage Formations on the Conductor.
  3. Enable the experimental visual designer, anchor your stage, and choose a line, arc, circle or two-row template.
  4. Drag performer dots, assign Bards, then save the diagram.
  5. Only when all clients are idle, out of combat and Performance, explicitly request SET POSITIONS & MOVE PARTY.
⚠Movement is opt-in, is subject to safety/path checks, does not teleport or rotate characters, and is not an automatic part of MIDI playback. The editor is experimental and off by default in the v0.32 manual.
Chapter 07

When the song falls silent

SymptomTry this
Timeline runs, no soundCheck ARM, full Performance UI, instrument, enabled tracks and C3–C6 range.
“Already running”Stop notes and stage movement, then run /windbound recover. ARM again.
Follower stays silentCheck party leader, same MIDI fingerprint, track assignment, follower role and instrument readiness.
Notes sound wrongInspect the track octaves, instrument tags and FFXIV Optimiser suggestions.
Stage dot won’t moveCheck vnavmesh, follower opt-in, the same ward/instance and a walkable destination.

For full diagnostics, recovery workflows and beta testing, use the official GitHub Wiki. Before sharing reports, remove sensitive local paths or character details.
